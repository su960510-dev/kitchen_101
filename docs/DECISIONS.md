# 결정 기록

슈퍼프롬프트의 작은 결정과 UX 보드와의 충돌 처리를 기록한다. 작성일 2026-11-03.

## 구조·기술

- **D-01 저장소 루트를 앱 루트로 사용.** 사용자가 지정한 `kitchen_101` 저장소에 바로 구성한다.
- **D-02 중복 위치 제거.** 저장소는 `infrastructure`, 매칭 가중치는 `domain/policies`에만 둔다.
- **D-03 네이티브 프로젝트 이름은 영문.** `expo.name`에 `주부1단`을 넣으면 한글이 제거되어 프로젝트 이름이 `1`이 되고 iOS prebuild가 `Could not find target '1'`로 실패했다. `expo.name=Jubu1dan`으로 두고 `plugins/with-display-name.js`가 표시 이름을 `주부1단`으로 지정한다. iOS·Android prebuild로 확인했다.
- **D-04 패턴 재사용.** 같은 계정의 이전 앱(Expo SDK 58)에서 검증된 metro 웹 헤더, 지연 로드 알림 어댑터, `useLoader`, `.web.ts` 파일 스텁 방식을 가져왔다. 서버 연동(Supabase 등)은 프롬프트 범위 밖이라 가져오지 않았다.
- **D-05 "오늘"은 KST 고정(+09:00).** 프롬프트 §4.4 요구대로 하며, 기기 시간대가 달라도 한국 포장 날짜가 하루 밀리지 않는다. 날짜는 `YYYY-MM-DD` 문자열이다.
- **D-06 알림 식별자에 날짜 포함.** `label:<id>:<날짜>:<발송일>` 형태라 날짜가 바뀌면 자동으로 취소·재예약된다. 09:00 KST 발송. iOS 예약 한도(64개)를 고려해 가까운 60개만 예약한다.
- **D-07 레시피 이력 정책.** 최근 5개 + 정착 대표 버전을 보존한다.
- **D-08 Android OCR 보류.** 프롬프트 순서대로 iOS 이후 구현한다. Android에서는 직접 입력으로 동작한다.
- **D-09 공유 메뉴 수신 미구현.** §6.2가 POC 선행을 요구하고 URL 붙여넣기를 필수 대안으로 둔다. MVP는 붙여넣기만 제공한다.
- **D-10 테스트에 `node:sqlite` 사용.** 모의 객체 대신 실제 SQL을 실행한다. Node 22.5 이상이 필요하다.
- **D-11 달력을 직접 구현.** 추가 네이티브 의존성 없이 기본값을 넣지 않는 날짜 선택을 보장한다.
- **D-12 커밋·푸시.** 프롬프트 §0은 승인 없는 푸시를 금지하지만, 사용자가 이번 요청에서 작업 완료 시 푸시를 지시했다. 스토어 업로드, EAS 프로젝트 생성은 하지 않았다.

## UX 보드와 슈퍼프롬프트가 충돌한 지점

원칙: 레이아웃·스타일·이미지는 보드를, 기능·문구·안전 정책은 프롬프트를 따른다. 프롬프트의 우선순위 1번이 식품 안전이므로 안전 문구는 보드보다 프롬프트가 우선한다.

| 보드 | 구현 | 근거 |
| --- | --- | --- |
| `3일 후 만료돼요!` | `3일 후 표시 날짜예요!` | §2.5 안전 단정 금지, §2.2 |
| `유통기한 임박 재료로 추천하는 레시피에요` | `날짜가 가까운 재료를 쓰는 내 레시피를 먼저 보여 드려요` | §7.2 |
| 목록에 날짜만 표시 `10.30 (목)` | `유통기한 11.06 (금)`처럼 종류 함께 표시 | §2.1 날짜 종류 분리 |
| 뱃지는 글자만 | 임박·경과 뱃지에 아이콘 추가 | §2.5 색상만으로 전달 금지 |
| 요일이 실제 달력과 다름(2026.11.05를 수요일로 표기) | 실제 요일 계산(목요일) | 정확성 |
| 예시 표시 없음 | 예시 데이터에 `예시` 뱃지와 안내 바 | §8.4 |
| 추가 화면에 이름 입력이 없음 | 이름 입력칸 추가, 나머지는 `자세히 입력하기`에 접음 | §5.1 필수 필드 |
| 추가 화면 날짜 라벨 `유통기한` 고정 | 기본 `소비기한`, 종류 변경 가능. OCR 결과는 인쇄된 종류 유지 | §2.1 |
| 탭 이름 `더보기` | 보드대로 `더보기`, 내용은 §8.1의 설정 | 보드 우선, 라우트는 `settings` |
| 냉장고 화면에 탭바 없음 | 보드대로 숨기고 뒤로가기로 복귀 | 보드 우선 |
| 레시피 상세의 북마크 아이콘 | 프롬프트에 즐겨찾기 기능이 없어 `우리 집 정착` 토글에 연결 | 프롬프트 범위 준수 |
| `레시피 저장` 버튼 | 내 레시피는 단계 메모 저장, 예시 레시피는 내 레시피로 복제 | §6.1, §6.4 |
| 추가 섹션 없음 | 홈 아래쪽에 파먹기, 엄마표, 날짜 미등록, 정착 레시피 추가. 첫 화면 구성은 보드와 동일 | §5.3, §8.2 |
| 인원수 조절 없음 | `필요한 재료` 제목 줄 오른쪽에 조절기 추가 | §6.3 |

## 예시 데이터

- **D-13 예시 날짜는 데모 전용.** §8.4는 현재 날짜 기준 임의 생성을 경계한다. 보드 재현을 위해 사용자가 선택할 때만 생성하되 `isSample`로 분리하고, 모든 행에 `예시` 표시, 안내 바, 알림·백업 제외, 한 번에 삭제를 적용했다.
- **D-14 예시 레시피 문구는 직접 작성.** 외부 콘텐츠를 쓰지 않았다.
- **D-15 보드 이미지의 권리 확인이 출시 전에 필요하다.** 사용자가 제공한 보드에서 사진을 잘라 번들했다. §11.2는 사용 허가가 확인된 자산만 번들하도록 요구하므로, 보드 이미지의 출처와 상업적 사용 권리를 `RELEASE_CHECKLIST.md`에 미해결 항목으로 남긴다. 보드 해상도가 낮아(1222×1287) 확대한 사진은 다소 흐리다.
- **D-16 앱 아이콘은 벡터로 재작성.** 보드 크기로는 1024px 아이콘을 만들 수 없어 같은 도형을 다시 그렸다. 라인 아이콘도 벡터로 다시 그렸다(§11.3).

## 2026-11-10 변경

- **D-17 구매일 기준 추정 보관 기한 자동 설정 (사용자 결정).** 슈퍼프롬프트 §2.3은 `구입일 + N일` 계산을 금지하지만, 사용자가 안내를 받은 뒤 이를 명시적으로 선택했다. 위험을 줄이기 위해 다음을 지킨다.
  - 포장 표시 날짜가 없을 때만 계산하고, 포장 날짜를 입력하면 그 날짜가 우선한다.
  - 새 날짜 종류 `ESTIMATED_FROM_PURCHASE`(`추정 보관 기한`)와 출처 `AUTO_ESTIMATE`로 저장해 소비기한·유통기한과 구분한다.
  - 품목명 단위로만 계산한다. 카테고리 일괄 규칙, 반찬 일괄 규칙, 냉동 연장 규칙은 두지 않는다. 엄마표 반찬에는 적용하지 않는다.
  - 기간 값은 출처가 확인된 데이터만 쓴다. USDA FoodKeeper(CC0) 기반 50개 품목(D-20).
  - 화면과 상세에 `참고 날짜`임을 표시하고, 지난 경우 상태를 직접 확인하라고 안내한다.
- **D-18 홈 냉장고 현황을 보관 장소별로 변경 (사용자 요청).** 신선식품·반찬·가공식품 대신 냉장·냉동·상온 개수를 보여 주고, 누르면 해당 보관 장소로 필터된 냉장고 목록을 연다. 카테고리는 등록 화면에서 항상 보이는 칩으로 고른다. 냉장고 탭 상단 묶음 탭은 요청 범위 밖이라 유지했다.
- **D-19 원격 푸시 권한 제거.** `expo-notifications`가 추가하는 `aps-environment`를 `plugins/with-local-notifications-only.js`로 뺀다. 로컬 알림만 쓰므로 필요 없고, 무료 Apple 개인 팀에서 프로비저닝이 실패했다. plugin은 `expo-notifications`보다 앞에 둬야 적용된다.

## 2026-11-10 변경 (2)

- **D-20 추정 보관 기한 데이터 확보.** FSIS 서버는 자동 다운로드를 막아, FoodKeeper 제품 시트를 CSV로 옮긴 공개 사본(jelera/food-shelflife-db, 2019-06-26)을 `data/foodkeeper/`에 두고 `scripts/build-storage-guidance.mjs`로 50개 품목을 매핑했다. 구매일 기준(DOP_) 값을 우선하고, 범위면 짧은 쪽, 개월은 30일로 환산한다. 원문에 없는 보관 방법은 계산하지 않는다(예: 토마토·우유 냉장 없음). 한국 품목명 매핑은 이 프로젝트의 판단이다(대파→green onion, 배추→cabbage, 무→radishes 등). 출시 전 FSIS 최신본(2025-01-22)과 대조해야 한다.
- **D-21 등록 화면 구매 개수, 상세 화면 직접 수정 (사용자 요청).** 등록 화면 기본 영역에 구매 개수(기본 1개)를 두고, 구매일과 보관 방법을 고르는 즉시 추정 보관 기한 카드를 보여 준다. 상세 화면 하단 버튼은 `저장`이며 이름·개수·단위·메모를 바로 고칠 수 있다. `다 먹었어요`와 `폐기로 기록`은 아래 보조 버튼으로 옮겼다. 일부 사용 카드는 개수 수정으로 대체했다.
- **D-22 개수 0 저장 시 삭제 (사용자 요청).** 상세 화면의 `다 먹었어요`, `폐기로 기록` 버튼을 없앴다. 개수를 0으로 두고 `저장`을 누르면 `개수가 0이라 (품목)이(가) 삭제됩니다.` 확인 창을 띄우고, 확인하면 품목과 사진을 완전히 삭제한다. 이 경로로는 소진·폐기 기록이 남지 않으며 복구할 수 없다. 이전에 기록된 소진·폐기 항목의 복구는 데이터 관리 화면에 그대로 있다.
- **D-23 붙여넣은 레시피 글 정리 (사용자 결정).** 링크 속 영상·페이지를 자동 분석하는 대신, 사용자가 직접 복사해 붙여넣은 글을 기기 안에서 규칙으로 재료·조리 순서로 나눈다(`recipe-text-parser.ts`). 외부 AI나 서버를 쓰지 않고 링크를 열지 않으며, 붙여넣은 원문은 저장하지 않는다. 결과는 편집기 초안으로 열려 사용자가 확인·수정한 뒤 저장한다. 프롬프트 §6.2의 '사용자가 본문을 직접 입력'하는 범위이며 공유·재배포 기능은 없다. 사이트 구조 데이터 자동 추출과 AI 분석은 사용자가 선택하지 않았다.
- **D-24 링크에서 레시피 불러오기 (사용자 결정).** 프롬프트 §6.2·§11.2는 외부 본문 자동 수집을 금지하지만, 사용자가 네트워크 접속과 본문·메인 댓글 기반 등록을 명시적으로 요청했다. 위험을 줄이기 위해 다음을 지킨다.
  - 사용자가 `링크에서 레시피 불러오기`를 누를 때만, 그 링크 하나만 기기에서 직접 연다. 서버·외부 AI를 쓰지 않는다.
  - 사이트가 공개한 schema.org Recipe 구조 데이터를 먼저 쓰고, 없으면 본문 영역(네이버 블로그 `se-main-container`·`postViewArea`, 티스토리 등)의 글만 읽는다. 네이버 블로그 PC 주소는 모바일 주소로 바꿔 연다.
  - YouTube는 영상·자막을 다루지 않는다. 공식 YouTube Data API v3로 설명란과 댓글 20개를 읽고, 작성자 댓글 → 인기 댓글 → 설명란 가운데 재료가 가장 많이 잡히는 글을 쓴다. 페이지를 긁지 않는다. API 키(`EXPO_PUBLIC_YOUTUBE_API_KEY`)가 없으면 붙여넣기를 안내한다. 고정 댓글 여부는 API가 알려 주지 않아 작성자 댓글로 대신한다.
  - 재료·순서만 초안으로 만들고, 페이지 원문·사진·영상·댓글 원문은 저장하지 않는다. 사용자가 편집기에서 확인한 뒤 저장하며 공유 기능은 없다.
  - 저작권·이용약관 위험은 남는다. 출시 전에 대상 사이트 약관과 YouTube API 서비스 약관을 확인한다.
- **D-25 인스타그램 게시물 캡션.** 인스타그램은 로그인 없이 열면 로그인 화면이지만, 링크 미리보기용 `og:description`에 게시물 캡션 전체를 공개한다. 사용자가 누른 링크 하나에서 이 캡션만 읽어 레시피를 정리하고, 로그인 화면·댓글·영상은 다루지 않는다. 캡션에 재료가 없으면 댓글을 붙여넣으라고 안내한다. 스레드·페이스북·틱톡은 불러오지 않는다. 인스타그램 약관의 자동 수집 제한과 충돌할 수 있어 출시 전 검토가 필요하다. 파서는 SNS 캡션 형식(이모지 제목, 소제목, 단위 없는 양, 여러 줄 단계, 팁, 해시태그)을 처리하도록 보완했다.
- **D-26 레시피 정리 규칙 (사용자 요청).** 원문을 그대로 옮기지 않고 모든 레시피를 같은 형식으로 맞춘다(`recipe-normalizer.ts`). 외부 AI 없이 규칙으로만 처리하므로 문장을 새로 쓰지는 않는다. 단위 통일(T·스푼·밥수저→큰술, t→작은술, cc→ml), 재료/양념 묶음, 괄호 설명은 메모로, 중복 재료 제거, 단위 없는 양은 지어내지 않고 '단위 확인' 표시, 단계는 장식(이모지·ㅎㅎ·!!·~·대괄호)을 지우고 마침표로 끝맺음, 팁은 단계에서 떼어 레시피 메모의 '팁' 목록으로, 제목은 첫 문장·최대 30자. 구조 데이터·본문·캡션·붙여넣기 모든 경로에 같은 규칙을 적용한다.
- **D-27 초안 전달과 키보드.** 정리한 초안을 화면 주소(JSON)로 넘기면 기기에서 깨질 수 있어 앱 메모리(`draft-store.ts`)로 넘기고 id만 전달한다. 하단 고정 버튼이 키보드에 가려 눌리지 않던 문제는 `KeyboardAvoidingView`로 고쳤다. `jubu1dan://recipes/import-link?url=`로 열면 링크가 미리 채워진다.
