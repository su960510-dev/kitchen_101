# 결정 기록

슈퍼프롬프트의 작은 결정과 UX 보드와의 충돌 처리를 기록한다. 작성일 2026-11-03.

## 구조·기술

- **D-01 저장소 루트를 앱 루트로 사용.** 사용자가 지정한 `kitchen_101` 저장소에 바로 구성한다.
- **D-02 중복 위치 제거.** 저장소는 `infrastructure`, 매칭 가중치는 `domain/policies`에만 둔다.
- **D-03 네이티브 프로젝트 이름은 영문.** `expo.name`에 `주부1단`을 넣으면 한글이 제거되어 프로젝트 이름이 `1`이 되고 iOS prebuild가 `Could not find target '1'`로 실패했다. `expo.name=Jubu1dan`으로 두고 `plugins/with-display-name.js`가 표시 이름을 `주부1단`으로 지정한다. iOS·Android prebuild로 확인했다.
- **D-04 패턴 재사용.** 같은 계정의 이전 앱(Expo SDK 58)에서 검증된 metro 웹 헤더, 지연 로드 알림 어댑터, `useLoader`, `.web.ts` 파일 스텁 방식을 가져왔다. 서버 연동(Supabase 등)은 프롬프트 범위 밖이라 가져오지 않았다.
- **D-05 "오늘"은 KST 고정(+09:00).** 프롬프트 §4.4 요구대로 하며, 기기 시간대가 달라도 한국 포장 날짜가 하루 밀리지 않는다. 날짜는 `YYYY-MM-DD` 문자열이다.
- **D-06 알림 식별자에 날짜 포함.** `label:<id>:<날짜>:<발송일>` 형태라 날짜가 바뀌면 자동으로 취소·재예약된다. 09:00 KST 발송. iOS 예약 한도(64개)를 고려해 가까운 60개만 예약한다.
- **D-07 레시피 이력 정책.** 최근 5개 + 정착 대표 버전을 보존한다.
- **D-08 Android OCR 보류.** 프롬프트 순서대로 iOS 이후 구현한다. Android에서는 직접 입력으로 동작한다.
- **D-09 공유 메뉴 수신 미구현.** §6.2가 POC 선행을 요구하고 URL 붙여넣기를 필수 대안으로 둔다. MVP는 붙여넣기만 제공한다.
- **D-10 테스트에 `node:sqlite` 사용.** 모의 객체 대신 실제 SQL을 실행한다. Node 22.5 이상이 필요하다.
- **D-11 달력을 직접 구현.** 추가 네이티브 의존성 없이 기본값을 넣지 않는 날짜 선택을 보장한다.
- **D-12 커밋·푸시.** 프롬프트 §0은 승인 없는 푸시를 금지하지만, 사용자가 이번 요청에서 작업 완료 시 푸시를 지시했다. 스토어 업로드, EAS 프로젝트 생성은 하지 않았다.

## UX 보드와 슈퍼프롬프트가 충돌한 지점

원칙: 레이아웃·스타일·이미지는 보드를, 기능·문구·안전 정책은 프롬프트를 따른다. 프롬프트의 우선순위 1번이 식품 안전이므로 안전 문구는 보드보다 프롬프트가 우선한다.

| 보드 | 구현 | 근거 |
| --- | --- | --- |
| `3일 후 만료돼요!` | `3일 후 표시 날짜예요!` | §2.5 안전 단정 금지, §2.2 |
| `유통기한 임박 재료로 추천하는 레시피에요` | `날짜가 가까운 재료를 쓰는 내 레시피를 먼저 보여 드려요` | §7.2 |
| 목록에 날짜만 표시 `10.30 (목)` | `유통기한 11.06 (금)`처럼 종류 함께 표시 | §2.1 날짜 종류 분리 |
| 뱃지는 글자만 | 임박·경과 뱃지에 아이콘 추가 | §2.5 색상만으로 전달 금지 |
| 요일이 실제 달력과 다름(2026.11.05를 수요일로 표기) | 실제 요일 계산(목요일) | 정확성 |
| 예시 표시 없음 | 예시 데이터에 `예시` 뱃지와 안내 바 | §8.4 |
| 추가 화면에 이름 입력이 없음 | 이름 입력칸 추가, 나머지는 `자세히 입력하기`에 접음 | §5.1 필수 필드 |
| 추가 화면 날짜 라벨 `유통기한` 고정 | 기본 `소비기한`, 종류 변경 가능. OCR 결과는 인쇄된 종류 유지 | §2.1 |
| 탭 이름 `더보기` | 보드대로 `더보기`, 내용은 §8.1의 설정 | 보드 우선, 라우트는 `settings` |
| 냉장고 화면에 탭바 없음 | 보드대로 숨기고 뒤로가기로 복귀 | 보드 우선 |
| 레시피 상세의 북마크 아이콘 | 프롬프트에 즐겨찾기 기능이 없어 `우리 집 정착` 토글에 연결 | 프롬프트 범위 준수 |
| `레시피 저장` 버튼 | 내 레시피는 단계 메모 저장, 예시 레시피는 내 레시피로 복제 | §6.1, §6.4 |
| 추가 섹션 없음 | 홈 아래쪽에 파먹기, 엄마표, 날짜 미등록, 정착 레시피 추가. 첫 화면 구성은 보드와 동일 | §5.3, §8.2 |
| 인원수 조절 없음 | `필요한 재료` 제목 줄 오른쪽에 조절기 추가 | §6.3 |

## 예시 데이터

- **D-13 예시 날짜는 데모 전용.** §8.4는 현재 날짜 기준 임의 생성을 경계한다. 보드 재현을 위해 사용자가 선택할 때만 생성하되 `isSample`로 분리하고, 모든 행에 `예시` 표시, 안내 바, 알림·백업 제외, 한 번에 삭제를 적용했다.
- **D-14 예시 레시피 문구는 직접 작성.** 외부 콘텐츠를 쓰지 않았다.
- **D-15 보드 이미지의 권리 확인이 출시 전에 필요하다.** 사용자가 제공한 보드에서 사진을 잘라 번들했다. §11.2는 사용 허가가 확인된 자산만 번들하도록 요구하므로, 보드 이미지의 출처와 상업적 사용 권리를 `RELEASE_CHECKLIST.md`에 미해결 항목으로 남긴다. 보드 해상도가 낮아(1222×1287) 확대한 사진은 다소 흐리다.
- **D-16 앱 아이콘은 벡터로 재작성.** 보드 크기로는 1024px 아이콘을 만들 수 없어 같은 도형을 다시 그렸다. 라인 아이콘도 벡터로 다시 그렸다(§11.3).
